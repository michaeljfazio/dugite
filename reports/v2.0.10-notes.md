# dugite v2.0.10

Patch release bundling the work merged since v2.0.9: byte-exact ledger/consensus
fixes, the Mithril V2 import migration, sync robustness, and at-tip metric
liveness. No breaking API changes. (On-disk snapshot format may require a
re-sync where noted in the underlying fixes.)

Validation milestone: during this release's preview soak, a **dugite-forged
block was confirmed on the Cardano preview canonical chain** — block 4396281
(hash `74f2786714…`), pool `ff9f5e5a…` (SAND), with a canonical child built on
it (Koios-verified). End-to-end block production by the Rust node is accepted by
the network.

## Ledger / consensus byte-exactness
- **PlutusV2 PV11 cost shapes (#771):** the on-chain apply path used VariantB
  division cost shapes for all protocol versions. At PV11 (van Rossem /
  VariantD), `divide/mod/quotient/remainderInteger` use different CPU/mem cost
  shapes; the hardcoded path over-/under-charged phase-2 budget. Now
  variant-aware at all 8 V1/V2 division sites — byte-identical at PV<11.
- **minFeeRefScriptCostPerByte → Rational (#766):** reference-script fee uses an
  exact `NonNegativeInterval` instead of a truncating integer division; the
  tiered fee accumulation matches Haskell's single-floor semantics.
- **Conway PParamsUpdate encoder keys (#769):** corrected the Babbage-offset map
  keys in the protocol-parameter-update encoder.
- **Unknown-language cost models preserved byte-exactly (#770):** cost-model
  entries for languages dugite does not yet model are round-tripped verbatim
  rather than dropped.

## Storage / Mithril
- **Mithril import via Cardano Database V2 (all networks):** the V1
  `/artifact/snapshots` endpoint was retired by the aggregators; import now uses
  the mithril-client `cardano_database_v2()` SDK end-to-end (list/get → verify
  chain → download+ancillary → Merkle verify) for mainnet/preview/preprod.
- **Deferred WAL rewrite on flush:** the per-flush full-window WAL
  re-serialize+fsync is deferred and reclaimed via slack compaction
  (byte-safe via crash-recovery prune), removing a steady-state CPU cost.

## Consensus / networking robustness
- **Live-apply wedge (#767):** snapshot/maintenance blocking I/O now runs under
  `block_in_place`, and the chainsync prune no longer convoys on the
  `candidate_chains` write lock — eliminating the all-parked stall; the residual
  per-boundary cascade self-recovers.
- **Stranded-snapshot wedge (#768):** detected and surfaced instead of
  busy-looping.
- **Praos bulk-sync peer-set collapse:** the forecast-park disconnect timeout is
  bounded (60 s at-tip / 300 s behind), and Slow-peer failures tear down the
  connection so the governor recovers — fixing the 0-peer wedge.

## Observability
- **At-tip metric liveness:** `dugite_treasury_lovelace` / `dugite_reserves_lovelace`
  and the governance gauges (`dugite_drep_count`, `dugite_proposal_count`,
  committee/pparam gauges) plus `dugite_utxo_count` are now refreshed per-block
  at tip, not only during bulk-sync / on forge. Previously they froze at the
  last catch-up value once at tip, reading one epoch stale across every boundary
  the node did not forge itself (the ledger was always byte-exact; this was a
  gauge-only staleness, but it misled epoch-boundary cross-checks).
- **Sync-saturation instrumentation:** added blockfetch active-peer / rx-byte
  gauges and corrected a mislabeled fetch-duration metric.
