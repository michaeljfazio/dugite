# dugite v2.0.5

Ledger-correctness and network-hardening release. Fixes a critical
genesis-mode Mithril bootstrap failure, a Babbage datum-witness false
rejection, and adds size-lying-peer attribution to BlockFetch. All fixes
validated live against mainnet/preprod and the Haskell reference.

## Fixes

- **ledger: datum witnesses required only for Plutus-locked inputs, not native
  scripts** (`eadec38afe`). A Babbage/Conway tx spending a native-script-locked
  UTxO that carries a `DatumHash` (with the preimage absent) was falsely
  rejected with `MissingDatumWitness` — 8 such confirmed mainnet txs were hit
  during sync at epoch ~434. Now gated on the locking script resolving to
  Plutus (Haskell `getInputDataHashesTxBody` / `isSpendingPlutusScript`); the
  collateral-return output datum hash is also added to the allowed-supplemental
  set (`getBabbageSupplementalDataHashes`). Pinned with a real on-chain tx
  fixture.

- **node: genesis-mode Mithril bootstrap no longer disconnects every peer**
  (`f03594a74d`, `8568248848`, closes #756). A `--consensus-mode genesis` node
  booted from a Mithril snapshot rejected every peer's first Conway header with
  a false `CounterOverIncrementedOCERT`, never applying a block. The per-peer
  eager opcert-counter map started empty and the validator fell back to counter
  0 for pools whose snapshot counter was > 1. Fixed by seeding the per-peer map
  from the snapshot counters, and by deferring the opcert upper-bound check
  (which the per-peer reconstructed counter cannot authoritatively enforce) to
  the body-apply path. Validated live on preprod.

- **ledger: bootstrap address-binding checks Byron INPUTS, not witnesses**
  (`e5cc177174`, closes #754). Legacy Daedalus dual-witnessing (vkey +
  bootstrap witness over the same key, all-Shelley inputs) was falsely rejected
  with `address_binding_failed`. The Shelley-era unidirectional check was not
  carried into Alonzo+ (`validateNeededWitnesses`: needed ⊆ provided). Validated
  against 6,263 bootstrap-witness mainnet txs incl. the exact false-positive
  class.

## Enhancements

- **node: size-lying peers attributed as protocol faults** (`069042b699`,
  closes #751). A BlockFetch peer that under-declares `block_body_size` could
  overrun the mux ingress backstop and die generically. Declared-size ranges
  now carry a hard receive-side byte limit (min(3× estimate + 1 MiB, 20 MiB
  ceiling, compile-time-bounded below the ingress limit)); exceeding it aborts
  the range as a `ProtocolError` with connection teardown (Haskell parity).
  Adds a per-`MsgBlock` 2.5 MB cap (`largeByteLimit`). Byron/average-estimated
  ranges stay unarmed (honest variance is unbounded there).

- **cli: `query treasury --output-text` prints exact lovelace** (`7c34cbf0b9`)
  alongside the ADA figure, for byte-exact pots cross-validation.

## Notes

- A forensic investigation (`reports/pots-deficit-fingerprint.md`) traced a
  ~996K ADA reserves over-allocation in one validation DB to a v2.0.2-line
  binary at boundary 388→389 — a **state artifact**, not a live-code defect
  (current code verified clean across 60+ live epoch boundaries; #755).
- Genesis-mode tip-following still stalls ~k blocks short of the live tip
  (Full-Genesis LoE/GDD/CaughtUp completion, #757) — use `--consensus-mode
  praos` (the default) to reach the tip. Tracked for a follow-up release.
