**One predicate was corrected after the run and re-applied to the same evidence**
(`69df146812`). Round 3 originally failed `chain_density=0.630 outside [0.400,0.600]`.
That flat ±20% band ignores sample size: block production is Bernoulli per slot with
p = activeSlotsCoeff, so at Round 3's 54-slot window one standard deviation is 0.068
density and ±0.1 is only ~1.5 sd — a healthy run fails about one time in eight. The
observed 0.630 (34 canonical blocks in 54 slots) is 1.9 sd, with 0 orphans, every block
seen by ≥3 observers, and 0 ERROR on all three nodes. The band is now the two-sided
p99.9 binomial interval, which is materially STRICTER wherever the sample supports it —
Round 2's band tightens from [0.400,0.600] to [0.461,0.539], so a density of 0.430 over
1813 slots now fails where the flat band accepted it. The correction was verified in
both directions before being applied. No other predicate was changed, and no evidence
was regenerated, moved, or hand-assembled for this report.

**The 3 tx-zoo failures are all `01a-simple-pay` from the Round 2 trickle racing
itself.** Verified for THIS run rather than carried forward: Round 2's logs contain 5
`Input conflict: input already claimed by mempool tx` lines and zero
FeeTooSmall/OutputTooSmall/ValueNotConserved/BadInputs. One address submitting every
20 s means the mempool's input-conflict check is working as designed. Round 1's zoo had
**0 failures**; its 3 non-PASS rows are state-skips that name their reason
(`no-rewards` ×2, `no-guardrails-script-in-constitution`).

**Known gaps, both open and documented:** #1067 (`NonMyopic.likelihoodsNM` hardcoded

every other query reads the pinned acquisition snapshot, so one LSQ acquisition can
answer from two ledger points; ~1 s window at tip). `09w-ledger-state` excludes only
