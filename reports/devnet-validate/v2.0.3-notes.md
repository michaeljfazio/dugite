## Genesis/CSJ liveness — #742 (fixed + system-verified)

After a full from-genesis ledger replay, the lock-free LedgerView/tip-watch kept its boot value (tip=Origin/0): the CSJ dynamo's first header parked forever in the forecast-horizon check — silent, CPU-idle, LoP paused. **Deterministic**, not a race.

- **Verification**: same db clone, same config — pre-fix binary: 0 blocks in 600 s after handover (loe pinned at tip, 1 dynamo/40 jumpers idle); fixed binary: 3,509 blocks in 120 s.

## Phase-1 oracle byte-exactness — #743 #744 #745 #746 #748 #749

59,574 false `FeeTooSmall` divergences on confirmed mainnet blocks (Babbage ep367+) plus four smaller classes, all root-caused and fixed byte-exact:

- **#743**: the Conway tiered ref-script fee was charged in Babbage/Alonzo. Now gated on PV ≥ 9 (Haskell: Babbage `getMinFeeTxUtxo = getShelleyMinFeeTxUtxo`; the term first appears in Conway `getConwayMinFeeTxUtxo`).
- **#744**: block-decoded txs had `tx_size = 0` (raw_cbor never populated) — the `min_fee_a·size` term was missing and the max-tx-size rule dead in the apply path. Full wire bytes are now reconstructed from preserved spans in every era decoder; fee-size = wire − 1 for Alonzo+ (`toCBORForSizeComputation`). Pinned end-to-end against three real mainnet txs (min fee 260,125 / 260,903 / 477,015 — exact).
- **#745**: `era_babbage`'s mint decoder missed the #730 zero-quantity prune → inflated `txInfoMint` → spurious phase-2 budget exhaustion (2 mainnet occurrences reproduced offline to the exact remaining-budget values).
- **#746 + #748**: intra-tx DELEGS sequencing for ALL stake-cert checks — registration, deregistration, and delegation now walk certificates left-to-right against the evolving state (Haskell DELEGS). Fixes false rejection of the legal `[dereg, re-reg, delegate]` mainnet pattern AND two forge-invalid-polarity gaps (`[dereg, delegate]` accepted; dereg-of-unregistered accepted with deposit-pot corruption on forge).
- **#749**: ref-input/input disjointness wrongly enforced at Babbage PV7/8 — Haskell's window is exactly `8 < pv < 11` (17 live divergences). Full PV matrix pinned.

After the fixes: **zero Phase-1/Phase-2 divergences** across live mainnet sync (ep385+, 100K+ blocks observed).

## Bulk-sync throughput — #747 (three root-cause layers, all found by live instrumentation)

1. **In-flight vs ingress invariant**: pipelined fetch bytes silently overran the per-protocol mux ingress queue, killing the active fetcher every 30-60 s (253 of 256 connection deaths) and cascading into CSJ dynamo rotations (~105/h) and 4.45× over-request. Window 4→2, ingress raised with a compile-time invariant against the real constant, mux exit reasons logged (were fully silent), per-claim cap.
2. **Estimate-based range sizing**: the 8 MB range budget bounded an average-based estimate, not actual bytes. Ranges now chunk by exact header-declared body sizes (Haskell `blockFetchSize` analogue) within **chain-adjacent runs** (split on prev-hash discontinuity AND filter gaps — `MsgRequestRange` delivers every block between two points, so a range must never span a hidden gap such as the overlap re-streamed after a dynamo rotation).
3. **Wire-vs-storage era-index off-by-one**: N2N wire headers carry the 0-based HFC NS index (Babbage=5, Conway=6); every wire-header consumer dispatched via the storage mapping (Babbage=6, Conway=7), so declared sizes never extracted and the byte accounting silently degraded to averages. New dedicated wire decoder; as a bonus this revives eager Conway header validation and the #735 far-ahead guard on Babbage (both silently inert before), with a new incomplete-view skip guard so eager validation can never partition genesis-epoch networks.

Plus: per-epoch 1.4 GB ledger snapshots rate-limited to 30 min during bulk sync (`SnapshotMinIntervalBulkSync`); the shutdown snapshot gets its own 120 s budget (#750).

**Measured live (same db, same peers, mainnet Babbage bulk sync)**: 32.5 → **55.1 blk/s sustained (+70%)**; fetcher deaths 95/h → 0; ingress overruns ~1/45s → 0; estimate-fallback ranges 100% → 0; over-fetch 4.45× → eliminated.

## Crash recovery — #752

A crash mid-flush could leave a gap in the persisted volatile chain that permanently wedged boot recovery (ledger far behind the ChainDB tip; BlockFetch refusing to re-fetch). `ChainDB::open` now prunes volatile blocks unreachable from the immutable tip (Haskell open-time validation parity); the pruned region re-fetches from peers.
