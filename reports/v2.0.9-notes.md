# dugite v2.0.9

Consensus-correctness patch. Fixes a Plutus builtin **flat wire-ID** mismatch
(shipped in v2.0.8 and earlier) and thereby fully resolves the Conway PlutusV3
ScriptContext divergence cluster (#761).

## Fix

- **#761 (Bug 2) — BLS12-381 + PV1.1.0 builtin flat wire-IDs** (`effd7aa626`).
  Plutus's `instance Flat DefaultFun` assigns builtin wire-tags **explicitly**,
  and that assignment DIVERGES from the `DefaultFun` data-declaration / `Enum`
  order in two places. dugite's `BuiltinId` discriminants had followed the
  declaration order, so:
  - **BLS G1 (58-60) / G2 (65-67)** were rotated: dugite had
    `hashToGroup, compress, uncompress` where the wire is
    `compress(58), uncompress(59), hashToGroup(60)` (and 65/66/67 for G2).
  - The **PV1.1.0 batch (89-100)** — array ops, `bls12_381_*_multiScalarMul`,
    value ops — was mis-ordered.

  Consequence: dugite **mis-decoded** any on-chain flat script using these
  builtins. E.g. a 1-arg `bls12_381_G1_compress` decoded as the 2-arg
  `hashToGroup` left a partially-saturated builtin that leaked into
  `appendByteString` — the `appendByteString: expected ByteString, got Builtin`
  phase-2 divergence on mainnet V3 SOP txs `71579b77` / `e998e761`. No state
  corruption (the node trusts on-chain consensus), but a wrong phase-2 verdict
  for BLS/array/value scripts — which would false-reject such txs at the tip /
  in the mempool, and matters for forging.

  Fix: reorder the `BuiltinId` discriminants in `term.rs` to the canonical Flat
  wire-tags, and reorder the positional DEFAULT cost table in `builtin/cost.rs`
  to match (it indexes by discriminant, so the rotation also mis-charged costs).
  **Oracle-verified byte-exact** against `IntersectMBO/plutus`
  `PlutusCore.Default.Builtins` (`instance Flat DefaultFun`, tags 0-100).

## How it was found

The bug surfaced in the post-v2.0.8 mainnet soak. An aiken differential first
*appeared* to implicate the CEK machine (aiken evaluated the applied flat term
to `(con unit ())` while dugite failed) — but the flat round-trip self-cancels
the wire-ID error (dugite decode→encode→aiken decode lands on the correct
builtin), so the real bug is dugite's **decoder**, confirmed by a direct
wire-tag comparison against canonical Plutus.
